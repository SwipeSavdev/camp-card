🧪 Sandbox Account Setup

⚠️ Important

Sandbox accounts are separate from real Apple IDs. Never use a real Apple ID for sandbox testing. Sandbox purchases are free and don't charge real money.

📝 Create Sandbox Tester Account

🚨 Error Handling Tests

Verify the app handles all error scenarios gracefully.

  • User cancels purchase
    Tap "Cancel" on Apple payment sheet → App stays on payment screen, no error shown
  • Network disconnected during purchase
    Enable Airplane Mode before tapping purchase → Appropriate error message displayed
  • Invalid product ID (dev test)
    If product ID doesn't exist → "Product not found" or similar error shown
  • Back button during purchase flow
    Tap back arrow → Returns to quantity selection without crash
  • App backgrounded during purchase
    Press home during Apple payment sheet → Resume app → Purchase completes normally
  • Authentication failure
    Enter wrong password 3 times → Apple shows error → App handles gracefully

🔍 Edge Case Testing

  • Rapid button taps
    Tap "Purchase" button multiple times quickly → Only one purchase initiated
  • App killed during purchase
    Force quit app during Apple payment → Reopen app → Purchase recovers or user can retry
  • Low storage on device
    App should not crash if device storage is low
  • Switch between quantity options
    Rapidly tap different quantities → UI updates correctly each time
  • Screen rotation (if supported)
    Rotate device → Layout adjusts correctly (Camp Card is portrait-locked)

🧾 Receipt Validation

Verify the backend properly validates Apple receipts.

📡 Backend Endpoint

POST https://api.campcardapp.org/api/v1/apple/verify-receipt

The mobile app sends the receipt to this endpoint after a successful purchase. The backend validates with Apple and provisions the Camp Cards.

  • Receipt sent to backend after purchase
    Check backend logs to confirm receipt validation request received
  • Backend validates with Apple servers
    Backend calls Apple's verifyReceipt endpoint and receives valid response
  • Camp Cards provisioned in database
    After validation, correct number of cards created for user
  • Transaction finished after validation
    App calls finishTransaction() to clear from Apple's queue
